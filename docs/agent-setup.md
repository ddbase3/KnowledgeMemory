# Configured document agent for KNOWLEDGE MEMORY

No fixed agent, separate model connector or retrieval service is created. An administrator selects an existing enabled agent in the single shared KnowledgeMemory settings UI. The settings record is managed by `ISettingsStore` under `knowledge_memory/game`. The selection is resolved through `IAgentConfigurationService`, not supplied by the player's browser.

The existing `IAgentExecutionService` is invoked once for keyword discovery and then once for each attempted single card pair. First it returns document-related keywords as one flat JSON array. For each subsequent call, the browser selects exactly one three-term combination at random, and the agent generates exactly one question-answer pair. Both calls use a fresh conversation ID and carry `agent_id` and `agent_config_group = agent` in the documented attachment context. Each pair's source fields are required, but are not independently verified by this plugin.

The first call aims for at least 100 terms from different document topics. JavaScript selects three terms for each attempt at random from that flat list and animates the current triple while that single-card request runs. Up to three card requests run concurrently on the same existing AJAX endpoint. Duplicates are checked only against the current round, and the progress counter advances only for accepted pairs. A temporary failure in one request does not discard successfully generated pairs. Each round limits attempts to six times the configured pair count to avoid uncontrolled model usage. The keywords are thematic hints, not mandatory connections. Each new round starts with an empty set of answers and seed choices, without additional storage.

The game AJAX action uses flat form fields in the existing single endpoint. It does not use JSON request bodies or an independent token service. Both stages require the same current BASE3 feature authorization, trusted host identity, POST and strict same-origin Fetch Metadata checks. Only the settings display may modify the shared agent selection.

**Important provenance boundary:** the agent's `source_title` and `source_excerpt` are generated assertions. The available `AgentExecutionResult` contract alone cannot prove they came from the authorized documents. Before deploying where document-only grounding is a strict requirement, verify the current MissionBay/AssistantRuntime retrieval output owner and expose trustworthy source spans there. Do not substitute a parallel retrieval mechanism inside this game.

Both game invocations override their local system prompt to an empty string. The game configuration remains owned by ISettingsStore and the settings UI appears only within the game; the old administration tab is removed without changing its existing feature permission ID.
